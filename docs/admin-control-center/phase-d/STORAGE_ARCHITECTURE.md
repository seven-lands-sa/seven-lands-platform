# Phase D — Storage architecture

**Nothing paid was provisioned and no production resource was touched.** This document defines the
seam the application already uses and the boundary an object-storage move must respect. It is a
design + contract document; the switch itself is an owner decision.

---

## 1 · Today (development and this phase)

| Aspect | Implementation |
| --- | --- |
| Bytes live in | `MEDIA_DIR` (default `./media`), written by Payload's local upload adapter. |
| Served from | `/api/media/file/:path*`, behind the collection's read constraint. |
| Delivery cache | `Cache-Control: private, no-store` — every file, every time. |
| Filenames | Generated by the pipeline (`safeStoredFilename`, `replaceStoredFilename`); the user's name is metadata only. |
| Deletion / replacement | Payload deletes the original and all derivatives on delete; replacement regenerates every derivative and moves the URL (content stamp). |

## 2 · The seam the application depends on

One module decides what a media URL is: `src/lib/content/media.ts`.

```
mediaUrl(doc, size?)        → path-only URL (`/api/media/file/…`) — origin-free by design
asPublicPath(url)           → strips any runtime origin off a Payload URL
absoluteFromCanonical(p)    → absolutises against https://sevnland.com for og:image / JSON-LD
resolvePublicMedia(doc, …)  → { url, width, height, alt, focal } or null for private/missing
mediaSrcSet(doc)            → responsive candidates, smallest derivative → original
```

Components never learn where the bytes live. Moving to object storage changes `mediaUrl`'s
implementation (or Payload's upload adapter) and nothing else in `src/`:

- nothing in the codebase builds a media URL by string concatenation;
- nothing stores an absolute media URL in the database (the URL is derived on read), so a storage
  move does not require a data migration;
- private visibility is enforced by access control, not by URL obscurity — which is what makes the
  next section safe when files sit in a bucket.

## 3 · Production boundary (documented, not provisioned)

Target: **Cloudflare R2** (S3-compatible) or any S3-compatible store, chosen by the owner.

### Buckets / prefixes

| Class | Object location | Delivery |
| --- | --- | --- |
| **Private originals + private derivatives** | private bucket (no public access, no public bucket policy, no public custom domain) | short-lived signed URLs only (minutes, not days), generated per request for authenticated staff (admin previews, and Phase E's draft preview). |
| **Public originals + public derivatives** | same bucket, `public/` prefix or a second bucket | served through the CDN (custom domain) **or** through the application route; either way the object is only there after an explicit `public` transition. |

The important asymmetry: the bucket is **not** publicly readable by default. Public visibility is a
per-object consequence of the editor's decision, never the storage default.

### Required adapter capabilities

1. **Public + private delivery** for both originals and every derivative.
2. **Signed access** for private objects, with a TTL short enough that revocation is real.
3. **Derivative paths** derived from the stored filename (`name-400x300.jpg`, `name-768x512.jpg`,
   `name-1200x900.jpg`) so the resolver's size map keeps working unchanged.
4. **Deletion** that removes the original *and* all derivatives (the media delete hook lists the
   files; the adapter must delete the same set).
5. **Replacement** that writes the new stamped filename and removes the previous original and its
   derivatives — the "old bytes stop being served" guarantee (verified locally in the replacement
   suite) must hold in the bucket too.

## 4 · CDN and cache policy — the revocation rule

The rule: **a URL whose visibility can change must never be cached immutably.**

| Situation | Policy |
| --- | --- |
| Public asset, any file route served by the app | `private, no-store` (today's setting; correct on day one of a CDN because it forbids shared caching). |
| Public asset served by a CDN in the future | short TTL (minutes) **plus** explicit purge on every visibility change, replacement and delete. |
| Private asset | never publicly cached; signed URL TTL bounds any leakage window. |
| PUBLIC → PRIVATE | purge, then the CDN refuses: the same URL that worked a second ago returns 403/404. Phase C measured the local equivalent at first request (73 ms public, 40 ms private); the object-storage move must preserve that behaviour, which is exactly why immutable long-lived caching is off the table. |

Because replacements already change the URL (content stamp), a replacement needs no purge to be
correct — the old URL simply stops resolving. Visibility changes are the case that *does* require an
explicit purge, and the swap decision must be made with that in mind.

## 5 · What must be decided by the owner before any migration

1. Provider + region (R2 is the default recommendation: no egress fees, S3 API, works with the AWS
   SDK adapter Payload already documents).
2. Whether public objects are served by a CDN custom domain (recommended: yes) or by the app route.
3. The signed-URL TTL for private previews (recommendation: 5–15 minutes).
4. A one-time migration of existing local files (dev/test only today — the development library
   currently holds no production assets, so the migration is expected to be trivial).
