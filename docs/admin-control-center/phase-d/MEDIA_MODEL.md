# Phase D — Media model

The Media collection is the single library every future content type will draw from. This document is
the authoritative description of what a media document is, what each field is for, and what was
deliberately left out.

Source of truth: `src/collections/Media.ts`, `src/lib/media/policy.ts`, `src/payload-types.ts`.

---

## 1 · Fields

| Field | Type | Purpose / notes |
| --- | --- | --- |
| `id` | number | Internal only. The admin never asks an editor to read, type or copy it — the picker returns it (Phase D §15). |
| `filename` | text (Payload file field) | The **stored** name. Always generated by the pipeline (§26): sanitised, lower-cased, extension derived from the sniffed content type — never from the user's string. Replaced binaries get a content stamp (see §6). |
| `sourceFilename` | text | The original upload name, kept **as metadata only**. This is what makes "the file the client sent" answerable without ever putting an arbitrary name on a path. |
| `mimeType` | text | Sniffed from magic bytes. The declared MIME must agree; a mismatch is refused (§6). |
| `filesize` | number | Bytes of the stored (normalised) file. |
| `width`, `height` | number | Pixels of the stored file, after orientation is applied. Used for layout stability (§46). |
| `url`, `thumbnailURL`, `sizes.*` | Payload file fields | Derivative URLs and their real dimensions. |
| `visibility` | select `private` \| `public`, required, default **private**, indexed | The governance switch (§5). Enforced at the byte level, not only in the UI. |
| `decorative` | checkbox, default false | Marks an image with no informational meaning: no alt text is required, readers announce nothing. |
| `alt` | text, **localized (ar, en)**, required unless decorative | First-class, per locale, `fallback: false` (§11, §12). |
| `caption` | text, localized | Optional editorial line. Also `fallback: false`. |
| `tags` | select, `hasMany`, controlled vocabulary | Lightweight classification instead of folders (§28): `brand · website · services · projects · articles · social · og · team · other`. |
| `focalX`, `focalY` | number (Payload native) | Focal point (§9). Stored as numbers, never as a CSS string. The admin editor writes 0–100; the public resolver normalises once to 0–1 (`focalPointOf()`), so no consumer can divide twice. |
| `contentHash` | text, indexed | SHA-256 of the bytes that are actually stored. Duplicate detection (§27) and replacement guard (§20). |
| `duplicateOf` | relationship → media | Set automatically when an upload's hash matches an existing asset. A **warning**, never a block. |
| `createdBy` | relationship → users | Who uploaded it. Written from the session, not from the form. |
| `replacedAt` | date | Last binary replacement. |
| `createdAt`, `updatedAt` | date | Payload standard. |
| `altStatus`, `usage`, `assetActions` | `ui` fields | Admin-only surfaces (locale completeness chips, "where is this used", replace/visibility/delete actions). They store nothing. |

### Derived, not stored

- **Usage references** are computed on demand by `findMediaUsage()` from an explicit registry of
  media-bearing paths (`src/lib/media/usage.ts`) — never cached, never stale (§16).
- **Alt completeness** is computed per locale (`library-meta`); the state an editor sees is
  `مكتمل / عربي فقط / إنجليزي فقط / مفقود` plus `زخرفية` for decorative assets.

## 2 · Visibility

- Two values only: `private` (default) and `public`.
- `private` is the state of every upload, whatever the uploader intended. Publishing comes later, on
  purpose.
- Read access: anonymous requests are constrained to `visibility = public` at the collection level,
  which Payload applies to the original **and** every derivative (the constraint matches
  `sizes.<name>.filename` too). Measured behaviour is in `MEDIA_SECURITY.md`.
- A private asset is refused to anonymous visitors even when the exact URL is known, and the refusal
  is a `403`, not a redirect to a placeholder.

## 3 · Localization

- `alt` and `caption` are localized with `fallback: false` (owner amendment #2, inherited from
  Phase C): a missing English value is **null**, never the Arabic text.
- Consequence for editors: the library shows "عربي فقط" rather than pretending the asset is fully
  described.
- Consequence for Phase E: the publisher can block publication when a page needs English metadata
  that does not exist. Phase D exposes the raw answers (per-locale values + completeness) but does
  not implement publishing gates.

## 4 · Tags, not folders

Folders imply a tree that has to be maintained and that hides assets from search. A controlled tag
vocabulary costs an editor nothing, keeps the grid searchable and is still sufficient for the
"brand / website / services / projects / social / og" grouping the owner asked for. Nothing in the
model prevents adding folders later if real usage ever demands them — the decision is documented, not
baked in.

## 5 · What was deliberately NOT added

| Rejected field / feature | Why |
| --- | --- |
| Free-form "description" long text | No consumer exists; captions already cover the editorial line. |
| Arbitrary file types (PDF, ZIP, video) | §6 — no product use case yet; every type added would widen the attack surface and the derivative logic. |
| Per-viewport image slots (desktop/tablet/mobile) | §10 — one responsive asset + focal point; art-directed overrides are a Phase E decision for the few components that genuinely need them. |
| DAM hierarchy, collections-in-collections, workflow states | §28 — out of proportion for a seven-capability marketing site. |
| A `usage` counter column | A stored counter is a stale counter. Usage is answered from the database at the moment it is asked. |

## 6 · Naming and replacement identity

- **Upload:** `safeStoredFilename(sourceFilename, sniffedMime)` → base name sanitised
  (unicode letters kept, emoji/control characters/slashes/dots removed, spaces → `-`, collapsed
  dashes, 80-char cap, lower-cased) + extension from the sniffed MIME. A `.jpg` that carries PNG
  bytes is stored as `.png`, because the bytes decide.
- **Replacement:** `replaceStoredFilename(currentName, newMime, hash)` → the asset keeps its base
  name, adopts the new extension and gains an 8-hex content stamp, e.g. `hero-workshop-9a02ffce.jpg`.
  Replacing again strips the old stamp first, so ten replacements produce `name-<stamp>.jpg`, never
  `name-1-2-3.jpg`.
- **Why the URL must change with the bytes:** browsers, CDNs, proxies and chat previews cache by URL.
  If a replacement reused the old URL, the old picture would keep being served from caches the
  application cannot reach. Tying the URL to the content is what makes "the old bytes are gone"
  true end-to-end (verified in the replacement suite).
- The **document** — and therefore every reference to it — never changes. Only the URL moves.
