# النشر والتدقيق قبل النشر

نقطة واحدة للنشر: `POST /api/pages/:id/publish { locales: [...] }` — وتمرّ إلزاميًا على مدقّق واحد
`src/lib/pages/publish.ts` (نفس المدقّق تستخدمه واجهة المشرف والاختبارات، فلا تختلف النتيجتان).

## ما يفحصه المدقّق (لكل لغة على حدة)

1. صفحة غير فارغة ولها عنوان.
2. كل قسم: هل نوعه معروف؟ هل له عارض عام؟ (وإلا: رفض بنص يشرح السبب).
3. الحقول الإلزامية للقسم **داخل اللغة نفسها** — عنصر مصفوفة فارغ = عدم اكتمال، ولا سقوط نصّي.
4. الوسائط: ملف غير موجود، أو خاص، أو بلا نص بديل مناسب = رفض يسمّي القسم والحقل والملف.
5. الأزرار: وجهة صالحة فقط.
6. رابط الصفحة المخصّصة: صالح وغير محجوز.
7. الصفحات الأساسية: اللغتان معًا.

## شكل الرفض

```json
{ "errors": [{ "message": "لم يجتز الفحص — لم يُنشر أي شيء." }],
  "blocked": ["en"],
  "blockers": [{ "kind": "media", "locale": "en", "sectionIndex": 2,
                 "sectionLabel": "…", "message": "«…» — الملف «…» خاص. لن نغيّر ظهوره تلقائيًا…" }] }
```

سلوك مضمون: **لا يُنشر أي شيء عند الرفض** (لا نشر جزئي)، و**لا تُغيَّر ظروف ظهور أي ملف** تلقائيًا،
وتُكتب محاولة الرفض في سجل التدقيق (`context.refused = true` مع أول سبب مسمّى) — لا رسالة عامة.

## الأدلّة المنفّذة

| الفحص | الدليل |
| --- | --- |
| رفض نشر بسبب وسائط خاصة (تُسمّي الملف) | `.phase-e-evidence/verify-media-gate.log` — ملف خاص مربوط بواجهة الرئيسية → `HTTP 400`، ولم يُنشر شيء، وبقيت حالة الملف `private`. |
| نجاح النشر للغتين | `21:57:39.722Z` / `.510Z` / `.960Z` (الصفحات #9 · #10 · #11) |
| ظهور النشر فورًا بلا إعادة تشغيل | `verify-runtime.log` — «بعد النشر: الوسم ظاهر = true» |
| رفض تغيير رابط صفحة منشورة | `verify-custom-page.log` — إعادة التسمية `HTTP 400` والرابط القديم ما زال يعمل |
