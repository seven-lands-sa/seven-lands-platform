# الإصدارات والاستعادة

## الإصدارات

كل حفظ (مسودة أو نشر) يُنشئ إصدارًا في `_pages_v`؛ السقف `maxPerDoc: 25` لكل صفحة. الاستعلام:
`GET /api/pages/versions?where[parent][equals]=<id>` — لاحظ أن `/api/pages/:id/versions` غير موجود في
هذه النسخة من Payload (قِيس: 404).

ملاحظة مهمة مثبّتة بالقياس: صف الإصدار يحمل **لغة واحدة** في كل مرة، فقراءة النسخ لا تصلح للحكم على
النسخة العربية والإنجليزية معًا؛ كل قراءة أو كتابة تُسمّي لغتها (§1).

## الاستعادة

`POST /api/pages/:id/restore { versionId }` — تفرض: صلاحية `pages.update`، ومطابقة الأصل (لا يمكن
استعادة إصدار صفحة أخرى داخل هذه الصفحة)، ثم `restoreVersion` + إبطال وسوم الكاش + حدث تدقيق
`page_restored`. واجهة Payload تعرض نفس العملية داخل تبويب الإصدارات.

## ما لا يفعله النظام

* لا حذف نهائي تلقائي لسجل الإصدارات.
* لا "استعادة" تعيد نشر صفحة تلقائيًا: الاستعادة تُنشئ مسودة/نسخة، والنشر يبقى قرارًا منفصلًا يمرّ
  على بوّابة النشر.

## الدليل

`verify-runtime.log`: `revisions stored for page 9: total=25` ثم `restore revision 211 → HTTP 200`
ثم بقاء المحتوى الأصلي بعد الاستعادة.
